## v1.3.0 新版本内容

本版本围绕视频相似度识别链路完成四轮优化，并修复完美匹配模式的高内存占用和分析结果列表不刷新的问题；同时继续完善视频合并功能的独立运行环境。识别算法的改动重点是让证据、缓存和执行过程更加一致、可解释和稳定，不以开发样本结果宣称对所有视频数据集都有精度提升。

### 一、视频识别与定位逻辑

- 统一识别过程中的视频、帧、匹配和报告契约，补充双向时序对齐与多片段聚合，支持对连续轨迹、包含关系和局部复用片段进行更一致的统计。
- 优化候选视频筛选和摘要构建，减少无关视频进入精确比较；保留双向候选命中，降低单向筛选造成漏掉潜在关系的风险。
- 新增有界的片段细化评估能力，可在已有候选片段上进行补充取样和边界复核；该能力默认关闭，不改变原有默认分析流程，也不能找回粗筛阶段已经漏掉的视频对。
- 完善时序、片段和窗口结果的结构化字段，保留覆盖率、轨迹、边界及证据状态，便于结果复核和后续评估。

### 二、批量分析速度与缓存性能

- 增加候选摘要热缓存，复用已生成的代表向量、哈希和视频摘要，减少重复读取特征和重复构建候选索引。
- 优化视频对执行调度和资源池复用，按数据局部性安排比较任务，减少索引反复创建和特征重复加载。
- 完善 SQLite 断点记录、恢复和增量复用逻辑，分析中断后可以继续处理未完成的视频对，并校验缓存身份、模型和参数版本。
- 优化预处理与特征提取阶段的资源管理和阶段指标记录，便于区分冷缓存、热缓存、解码、嵌入、候选筛选和精确比较的耗时。

### 三、完美匹配模式内存优化（重点）

- 动态抽帧默认使用 OpenCV 顺序解码，只保留当前解码帧，避免高分辨率或竖屏视频使用 Decord 批量读取时产生持续增长的原生缓冲；OpenCV 在未输出任何帧且打开失败时才回退到 Decord。
- 增加解码后端、回退原因和阶段资源指标，便于定位异常视频和确认实际使用的解码路径。
- 完美匹配模式继续支持流式特征提取和有界批处理，避免一次性将长视频的所有帧和向量同时堆积在内存中。
- 特征缓存 schema 升级到 v5。由于抽帧后端契约变化，旧缓存会按规则失效并重建，避免复用不同解码策略产生的结果。
- 开发环境的长视频验证中，完整流程峰值 RSS 约为 1.08 GB；实际占用仍取决于视频分辨率、帧数、模型、设备和并发配置。

### 四、报告列表与结果保留

- 修复进入报告页面时列表不主动刷新，导致不同分析配置生成的报告已经存在但界面仍显示旧列表的问题。
- 当前报告按完整报告路径匹配和自动选中，避免同一批视频使用不同配置时被错误视为同一报告。
- 报告视图不再持久化旧的分析选项状态，并兼容清理历史状态；已有报告文件不会因本次修复被删除或覆盖。

### 五、视频合并与运行环境

- AI 识别运行环境与视频合并运行环境分离管理，合并功能使用独立的 `merge-env`，避免升级识别依赖时影响合并工具。
- 完善合并运行库的检测、配置和状态展示；已存在运行库时复用本地环境，应用更新不需要重复下载。
- 保留上一版本的合并编辑、时间线、预览和低内存导出优化。

### 六、升级兼容性与验证

- 已安装用户升级到本版本通常不需要重新安装 AI 运行时、CLIP 模型或 FFmpeg；首次使用且本地不存在独立合并环境时，仍需按界面提示准备 `merge-env`。
- 由于特征缓存 schema 升级，首次重新分析已有缓存时可能需要重建一次帧缓存；旧报告仍可读取。
- 普通、快速、完美匹配等预设的现有参数语义保持不变；片段细化评估默认关闭，需要时单独启用。
- 已完成 Python、Rust、前端单元测试以及 CUDA/流式内存相关验证；不同硬件和视频库上的实际速度、内存和召回率仍应以本机数据为准。

## 下载建议

普通用户只需要下载一个与系统对应的应用包：

- Windows CPU 安装版（推荐大多数用户）：`Video_Similarity-v1.3.0-windows-x64-cpu-installer.exe`
- Windows GPU 安装版：`Video_Similarity-v1.3.0-windows-x64-gpu-installer.exe`
- macOS M 系列：`Video_Similarity-v1.3.0-macos-arm64-installer.dmg`
- macOS Intel：`Video_Similarity-v1.3.0-macos-x64-installer.dmg`
- Linux Debian/Ubuntu：`Video_Similarity-v1.3.0-linux-x64-installer.deb`
- Linux Fedora/openSUSE/RHEL：`Video_Similarity-v1.3.0-linux-x64-installer.rpm`

不想安装时，可以选择同平台文件名中带 `portable` 的便携包，解压后直接运行。
